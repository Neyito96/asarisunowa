# 新着100件（EP-06592〜06691）の増分判定と掲載件数の再計算（READ_ONLY）

## 確定済みの前提（司令塔の実測 2026-11-10、再実測しない）
原本 6,691 EP-ID／旧判定タブ 6,591／差分 EP-06592〜06691 の100件／旧EP-ID消失0／原本重複0／承認済み掲載基準 5,848（2026-10-22）／旧比較対象 5,219。約5,936は旧試算で確定値ではない。

## 方針
- 10/22凍結基準（`docs/audits/2026-10-22-publication-scope/decisions.json.gz`）は変更しない。新着だけを同じ基準で判定する。
- 宇宙掲載（publication）とおんさ比較（comparison）は別々に判定。ニュースの学校は宇宙候補として保護し比較は対象外。こどもそうだんしつは掲載採用・比較外。
- 未確認（GUID/題名/日時の欠落、未知番組、同題同日で別ID、再配信語）は**保留**。無条件で公開対象にしない。GUID一致の重複は対象外（重複）。
- 「アンコールの舞台」は再配信ではない（EP04305の誤除外防止）。
- 台帳整合（旧IDの消失・重複・不正ID）が崩れていれば判定せず停止する。物理削除・再採番はしない。

## おんさ比較（司令塔の3資料実査を反映）
- 計数定義は `scripts/lib/onsa-count.mjs` の `SPEC` に集約（出典: `speakers3.js`、司令塔が確認した内容）。6番組（genba/media/sdgs/houdan/donuts/sports）のみ、ニュースの学校は含めない。SDGsは 2026-06-30 以降を除外（JST想定・要検証）。`（再）`/`（ふりかえり）`/`（深掘り）`始まり、`再放送です`を含む題名は actualDuration=0 として**画面カウンタに数えない**。
- 出力は「API生配列件数」「readData後」「画面カウンタ相当」を別々に持つ。5,512は画面カウンタの値であり、生配列件数ではない。
- `--onsa` は生API JSONを直接受け付け、schema不一致・取得不能は `unavailable`（過去値は再利用しない）。
- EP同一性は GUID/Omny clip → Spotify episode ID → 番組+題名+JST日付 の順。差分は EP単位で「新着 / 再配信 / 旧SDGs / 日時差分 / 番組構成 / 未解明」に分類し、逆方向（旧比較対象なのにおんさ側に無い＝不足）と同一EPへの多重対応（重複）も出す。基準日時が違うので差を収蔵漏れと断定しない。
- 未検証の前提: `sports` を「スポンジ」に対応付けている点。EP同一性が取れた項目で裏付けるまで確定扱いにしない。
- Issue #275 の監視は `scripts/onsa-count-watch.mjs` + `.github/workflows/onsa-count-watch.yml`（6時間毎・手動、最小権限、Secrets不要、変化/失敗/監視空白をIssueへ記録）。同じ計数定義を使う。

## 第4指令対応（実データ受領後）
- **増分モード**: `--increment <新100行CSV> --audit-evidence "<旧全件存在・ID一意の外部確認>"`。旧6,591の凍結判定snapshotを基準に新100行だけで判定。証拠文字列が無ければ停止。完全照合は `--ledger` で維持（旧EP-ID消失・重複・不正IDで停止）。
- **旧GUIDの優先照合**: 旧判定タブH列の公式GUID（`old-guid-evidence.csv`、司令塔実測）→ 旧台帳G列 → 旧側の題名+日付（公開済み5,848+除外618の公開データ）の順。旧G列が空でも重複を検出。新06595/06596/06597 = 旧03857/03858/03861 は「対象外(重複)」、旧EPは採用のまま保持。
- **新側は公式採用にしない**: 通常・学校・こどもそうだんしつの97件は「掲載候補(未審査)」止まり（publication=保留、review=未審査(候補)）。
- **実CSVの結果**（`increment-manifest.json` / `publication-recount.json`）: 新100件 = 候補97 / 保留0 / 確定除外3(重複)。承認済み確定分 **5,848**、審査後の最大候補 **5,945（上限・確定値ではない）**、台帳総数6,691。過去分取込（配信日が10/22より前）22件を区別して記録。番組別: 現場24・スポンジ10・学校14・MEDIA TALK 15(+重複3)・ドーナツ20・報談7・こども7。
- **#275 キャッシュ修正**: 復元先と保存先が `prev` / `out/onsa-count.json` で食い違っていたため、両方を `state/` に統一。キーは毎回ユニーク、復元は接頭辞で最新を取得。skipped/失敗でも保存し、直近の成功値(`lastOk`)を保持。ローカルでキャッシュの保存→復元を再現するテストを追加。
- **提供者上限の遵守**: 1リクエスト/実行・再試行なし、最短間隔5時間（手動0.5時間）、自己上限24回/日（提供者上限1万の1/400以下）。取得不能は `unavailable`（数字を作らない）。

## おんさ画面の計数条件（speakers3.js を読み取り専用で確認）と293件の要因分解
出典: `yoshimotomasahir/asapoki_vis` `speakers3.js`（取得時点HEAD `3016b1f`、AGPL-3.0-only）。**コードは複製せず、規則だけを独自実装**し、出典とライセンスを `scripts/lib/onsa-count.mjs` に明記。
- 画面カウンタ `num_title` は `actualDuration>0` の話だけを加算。`actualDuration` は `duration`(秒)で、題名が `（再）`/`（ふりかえり）`/`（深掘り）`始まり、または `再放送です` を含むと0。したがって **duration が0/欠損の話も数えない**。
- 既定フィルタ: 6番組すべて選択、長さ0〜999分、月範囲 2020年8月〜閲覧時の当月。SDGsは `new Date(2026,5,30)` 以降をスキップ。各エントリに `mc[]`/`speakers[]` が無いと読み込みが例外で打ち切られる。
- **画面は同一エピソードの重複エントリを除かない**。APIが重複を除いているかは未確認（API本体は取得不能）。

### 添付の共同編集シート書き出し（API本体ではない参考再現）による分解
- 6番組タブ（学校・YouTube等は対象外）を上記の規則で数えると、画面カウンタ相当は **5,785**。このうち同一linkが複数タブに出る重複エントリが **290**（現場タブが総合フィードで専用番組と重なる: 現場+スポンジ138、現場+報談121、現場+ドーナツ9、メディア+スポンジ5、メディア+ドーナツ9、SDGs+スポンジ8）。重複を除くと **5,495**。管理人スクショ(11/10 09:14)の 5,512 との差は **17**（シートの書き出し時刻差、または未確認のAPI側処理）。
- 5,495件をEP単位で台帳側（旧公開5,848+除外618の公開データ＋新100件）と 番組+題名+JST日付 で照合: 5,432件が一致、63件は照合できず（未解明）。
- **旧比較対象 5,219 と 5,495 の差 276 = 466 − 190**:
  - 旧比較対象に入っていないおんさ側の項目 **466**: 旧保留(同一性保留) 85（現場77・MEDIA TALK 5・報談2・スポンジ1）／番組構成(旧判定「重複」) 127（報談119・MEDIA TALK 8）／期間・日時差分(旧比較は保留・掲載は日時差分で採用の群) 106（報談88ほか）／新着(EP-06592以降) 76（現場24・ドーナツ20・MEDIA TALK 15・スポンジ10・報談7。新100件から学校14・こども7・重複3を除いた数と一致）／旧SDGs 9／**未解明 63**（台帳側に照合できない。MEDIA TALK 33・SDGs 9・現場7・報談6・ドーナツ6ほか）。
  - 旧比較対象なのにおんさ側に無い **190**（現場119・MEDIA TALK 37・スポンジ13・ドーナツ12・SDGs 9。うち13は題名規則で非計数、177は照合できる項目なし）。
- 管理人実測 5,512 − 5,219 = **293** は、上の 276 と、時刻差/未確認処理の 17 に分かれる。**説明可能 403 項目、未解明 63 項目、不足 190 件**。これは「収蔵漏れ」の判定ではない。
- 注意: この分解はAPI生JSONではなく共同編集シートの書き出しに基づく。APIの重複除去ルールと取得時刻が確認できれば更新する。`onsa-diff.json` に重複あり/なしの両方を保存。
