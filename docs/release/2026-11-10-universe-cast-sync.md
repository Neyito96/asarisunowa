# 台帳の出演者確定変更を蔵・宇宙(非公開プレビュー)へ同期(第20号)

状態: Draft PR・ローカル・READ_ONLY・非公開プレビューのみ。本番GAS・Spotify・トリガー・main・公開サイトは未変更。

## 原因
`scripts/build-universe-preview.mjs` は既存エピソードについて「Spotify URLの補充」だけを台帳から読み、出演者(X列=23、AT〜AX列=45〜49)を読んでいなかった。台帳で出演者を直しても、宇宙のプレビュー(詳細・番組別一覧・検索索引)には届かなかった。

## 修正
- `public/library/cast-sync.mjs`(純粋関数): `refreshCastFromLedger(existing, rows)` が EP-ID 単位で台帳の出演者を読み、X列とAT〜AX列を人物単位で重複なしに整理(既存の `dedupeCast`)して、既存エピソードの `cast` を追加/置換する。
- `buildPreview` が上記を呼ぶ。詳細・番組別一覧・検索索引は同じ `episodes` から1回で書き出されるため、構造上同じ出演者になる。整合は `verifyCastConsistency` で別途検証。
- **台帳のみが真値**: 概要からの抽出(gap-audit の `extractCast`)や補完提案は一切使わない(人間が確定した出演者を推測で上書きしない。試験で確認)。
- **台帳が空欄の時は既存値を消さない**(`keptBlank` として件数のみ報告)。出演者を全員外す訂正は、この方針では反映されない(要・別途明示操作)。
- **冪等・増分**: 同じ入力で再実行すると変更0。追加訂正(例: 神田→杢田の入替)は次回同期で差分だけ反映。固定件数に依存しない(試験は生成条件から期待値を導出: 500件/7例外、40件/1例外、12件/例外なし、500件/12例外)。
- **未レビューの新着**は従来どおり暫定・未レビュー・公開不可(`manifest.preview.provisional=true`)で、出演者同期はそれを変えない。

## 検証

## 実データ(ニュースの学校500件)での確認は未了 — 次の1手
本番台帳の ニュースの学校500行は、現在のREAD_ONLY書出(COPY書出ガード、**1承認=1ファイル・200行上限**・更新対象IDは承認記録のrefresh)では取得できていない。500行を取るには ①書出ガードの上限を250行×2ファイル、または専用の読取関数で複数回に分ける承認、②既に承認済みの経路で**ニュースの学校の更新対象EP-ID一覧**(出演者列のみ)を出す、のいずれかが要る。コードは行数に依存しないため、取得できた時点で `build-universe-preview.mjs` → `verify-universe-cast.mjs` を実行すれば、管理人の入力(神田493/杢田7)がそのまま非公開プレビューの検索結果になるかを確認できる。それまでは「500件で493/7になる」ことは**未実測**(合成データでの自動テストのみ)。
データ品質の所見(参考・今回は変更しない): 既存データには役割語つきの表記(例「MC○○」「音源編集○○」)が人物の別名として混在している。`dedupeCast`は同名判定が表記依存のため、検索件数が表記ゆれで割れ得る。台帳側の正規化が望ましい。
