## 3. 推奨: 「A を土台に、B の最小新規部分だけ足す」(C は今は採らない)
1. **蔵は現行台帳を唯一の正本として凍結保全**。書込みは増やさない。
2. **単一exporter→公開JSON(契約)** を唯一の出口にする(既存 `export-library-public.mjs` を拡張)。契約に `serviceLinks`(個別EP URL・番組止まりを区別)と `descriptionSource` を明示し、**再出力ゲート**(件数・ID集合=公開判定、旧版との差分レポート、欠損レポート、固定件数なし、失敗時は旧版維持)で守る。再出力漏れは「古さ検知」(台帳の最終更新日と公開スナップショット日)で警告。
3. **田の新機能=薄い静的ページ `public/collection/`**(本PRの試作): 検索→選択→並べ替え→サービス切替→コピー/共有URL/メール。サーバー・DB・認証・有料API不要。公開データ契約だけを読む。
4. **宇宙は現行を維持**し、同じ契約を読む。接続は URL 連携(`collection/?add=EP-…`)から始め、宇宙側の変更は別リポジトリの別PRで段階的に。
5. **公式プレイリスト同期は段階C**: 能力が確認できたサービスだけ・本人認可後。それ以外は段階B(リンク集)で同等体験。Spotify同期は既存の設定駆動エンジン(#292)を隔離して再利用する。
6. 旧PR群は機械的に捨てず、固有資産を判定(`2026-11-10-pr-audit-and-go-nogo.md`)。

C に切り替える条件(実測で示せたときのみ): 台帳の列構造が出力契約を作れない/書込み競合が解消できない/Sheetの規模限界。現時点でいずれも未確認。

検索(キーワード/番組)→「追加」→集に並ぶ(↑↓✕)→サービス選択(個別リンクの有無を3状態で表示: 個別あり/番組ページのみ/未登録+代替)→「リンク集をコピー」「共有URLをコピー」「メールで送る(メールアプリを開くだけ)」。保存はブラウザ内、共有URLは `#c=` トークン(サーバー不要)。宇宙・図書館から `?add=` で追加可能。

## 8. 重大リスクと対策(実装着手前の洗い出し)
1. **公開データを丸ごと再出力して人間判断を失う** → 再出力は旧版との差分ゲート必須(ID集合=scope、件数は導出、旧版維持のロールバック)。
2. 台帳への書込み事故 → 新規コードは読み取り専用。書込みは別承認・COPY限定。
3. 出演者の誤帰属 → 台帳値のみ(推測禁止)。#294は非破壊・冪等・上書き0。
4. 番組URLと個別URLの混同 → `classifyLink` で区別(実データでApple番組URL1件を検出)。
5. 共有URLの互換性 → トークンに版数 `v:1`、不正値は拒否(テスト済み)。
6. 本文の公開 → W本文は非公開経路が確立するまで公開リポジトリに置かない(#295のプロトコル)。
7. 切替失敗 → 試作は未リンクの別パス `/collection/`。既存ページ・本番は不変。
