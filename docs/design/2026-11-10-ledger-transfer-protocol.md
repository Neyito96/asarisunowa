# 台帳(蔵)→GitHub 監査データ受け渡しプロトコル(管理人は転送係にならない)

## 前提(実測)
- リポジトリ `Neyito96/asarisunowa` は**公開**。Claudeのセッションは**このリポジトリ限定**で、Gistや他のAPI、Actionsのsecretsには到達できない(403)。Claudeの本番台帳取得は、コネクタが14MBを会話に返すだけで保存不能のため不可。
- ChatGPT側のGoogle Sheetsコネクタは本番台帳の範囲取得(約200行ずつ)に成功済み(Issue #283)。
- 公開データには既に「清掃済み概要」が掲載される設計。**機微なのは原文V列(連絡先ブロック等)・非公開列・個人情報**であり、W列(清掃済み)は公開予定の本文。ただし承認前の本文を公開PR/Issueへ置かない方針を優先する。

## 推奨: 非公開リポジトリ経由(本文を公開GitHubに出さない)
1. ChatGPT側で**非公開**リポジトリを用意(例: `Neyito96/asarisunowa-private-transfer`。既存の非公開リポジトリのブランチでも可。管理人の操作は不要=ChatGPTのGitHub権限で作成)。
2. 受け渡しファイル `transfer/YYYY-MM-DD/ledger-w.jsonl` をそこへコミット。
3. Claudeは `add_repo`(読み取り)でその非公開リポジトリをセッションに接続して読む。接続できなければ「接続不可」とIssue #283に書く(推測で進めない)。
4. 公開リポジトリには**検証結果(件数・ID・エラーコード)だけ**を書く。本文はレポートに出さない(`apply-description-transfer.mjs` はそう実装)。

## 取得対象(IDのみ・公開可)
- 第1優先: `tests/fixtures/news-school-cast-2026-11-10.json` の500 EP-ID(ニュースの学校)。
- 第2: `tests/fixtures/published-description-gaps-2026-10-21.json` の `rawRendered`(公開データで清掃済み未反映の全ID)。実測で学校以外にも未反映があるため。
- **取得列はA(EP-ID)とW(概要清掃済み)のみ**。V(原文)・他列は取得不要(Wが空のIDは `W_BLANK` として報告するだけ)。

## 受け渡しファイル形式(JSON Lines, UTF-8)
```
{"_meta":{"sheet":"1lLgLzg…FG4","tab":"エピソード台帳","snapshotDate":"2026-11-10","readAt":"ISO8601","readRanges":["A81:A872","W81:W872",…]}}
{"id":"EP-00081","w":"<W列のセル値そのまま>","wLen":123,"wSha256":"<任意: w(UTF-8)のSHA-256>"}
```
- `id`=`^EP-\d{5}$`、`w`=セル値そのまま(加工しない。改行は可)。`wLen`(文字数)・`wSha256` は任意だが、あれば**破損・切り詰めを検出**して不一致行は採用しない。
- 1ファイル1MB程度(500行)まで。範囲が複数回に分かれても1ファイルに連結してよい。重複IDは両方不採用。
- 検証(`scripts/apply-description-transfer.mjs`): 不正ID/重複/空W/SHA・文字数不一致/個人情報らしき文字列(メール・mailto・電話)は**その行を保留**(公開データへ入れない)。

## Claude側の処理(自動)
1. `--check TRANSFER.jsonl DATA_DIR`: 書込なし。要修正件数(原文表示→清掃済み、文面差)をID集合別に確定。
2. `--write TRANSFER.jsonl SRC OUT`: 概要だけを差分反映。出演者・リンク・公開範囲・件数は不変。再実行で変更0。
3. 検証(`scripts/verify-site-data.mjs`、`tests/site-integration.cjs`)→ Draft PR(#295。#294の出演者修正とは別PR・別コミット)。
4. 結果をIssue #283に記録(件数のみ)。

## 代替(非公開リポジトリが作れない場合)
- 本文を含めずに済む**ハッシュ照合のみ**: 行ごとの `wSha256`+`wLen` だけを公開Issueコメントへ置く。要修正件数は確定できるが、修正データ自体は作れない。
- 修正データまで進めるには本文が必要。その場合に限り、**公開前提の清掃済みW列のみ**を、PR #295 の専用ブランチへ一時コミットする案を管理人が許可したときだけ実施(ブランチは作業後に削除。Git履歴・フォークに残り得る点を承知の上)。既定では行わない。
