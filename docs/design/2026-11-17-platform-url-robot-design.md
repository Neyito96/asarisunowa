## 0. 方針（変えないこと）
1. **管理人がGASを押して走らせる**。Claude は設計・実装・テスト・COPY試験まで。通常運用で Claude のクレジットを使わない。
2. **本人確認の基準は緩めない**。各回の固有番号（公式GUID）または音声ファイルが一致したもの、あるいは「番組・題名・配信時刻±60秒・長さ±2秒」がすべて一致したものだけを採用。それ以外は保留。URLを推測で組み立てない。
3. **空欄にだけ書く**。既に入っているURLと違う候補は上書きせず「別URLあり」として一覧に出す。
4. 書く前に履歴を残し、書いた後に読み戻す。自分が書いた値だけを戻せる。上限・停止旗・ロック・承認は P26 と同じ仕組み（docs/operations/2026-11-15-p26-production-runbook.md）。
5. 確実な取り口がない配信先は**番組単位のリンク**（その番組のトップページ）にとどめ、回ごとのURLは空欄のまま「未対応」と表示する（架空のリンクを作らない）。

## 1. 全体の形
既存の P26（本番ロボGAS「朝ポキ｜本番ロボ」に置いた手動専用ファイル）を土台に、**配信先ごとの「取り口（アダプター）」を差し替えられる1本のロボ**にする。名前は「P27 配信先URLロボ」。

```
[取り口] 配信先ごとに、その番組の全エピソード一覧（ID・題名・配信日時・長さ・音声URL/GUID）を取る
   ↓
[照合] V2 の各回（EP-ID・番組・題名・配信日時・長さ・公式GUID・音声URL）と1対1で結ぶ ……確認の強さを記録
   ↓
[計画] 空欄の枠だけ・URLの重複なし・形が正しい（配信先ごとの書式チェック）→ COPY「P27・計画」
   ↓
[反映] 承認当日だけ・上限つき・履歴→書込→読み戻し（V2の配信先列だけ）
   ↓
[開く確認] 書いたURL・既存URLを実際に開き、正しい回のページか（題名が出るか）を確かめる → COPY「P27・開く確認」
```

### 下調べ関数（読むだけ・最初に1回）
`P27_0_下調べ_READ_ONLY`：Pocket Casts・Pody・Amazon の番組ページを1回ずつ取得し、次の4点を表にする。
- 回ごとのIDや題名がHTMLの中に載っているか
- 一覧のJSONが含まれているか
- 取得できたか（403・JavaScriptが必要、など）
- 何件の回が見えたか

この表を見て、取り口を実装するか番組単位にとどめるかを決める。ここで推測はしない。

## 3. 開く確認（全配信先共通・読むだけ）
- `P27_6_開く確認_READ_ONLY`：V2の7列に入っているURLを、1回あたり上限（例 400件・6分以内）で順に開く。
- 記録する項目: 状態（200／転送／404）、ページに出る題名、V2の題名との一致。
- 続きから再開できる。全件（約1.7万URL）は数日に分けて実行する。
- 404や別の回だった場合は「要確認」に載せるだけで、**自動では消さない**。直すかどうかは管理人が決める。

4. 手順書 `docs/operations/…-p27-runbook.md` を書く。各関数の期待ログ、止める条件、戻し方を載せる。
5. 置き場所は、Spotify の認証が既にある本番ロボGASが向いている（P26 と同じ）。そこは Claude から編集できない場合があるため、そのときは**ファイルを1つ貼り付けてもらう手順**を手順書に書く。
