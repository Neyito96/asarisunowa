## 変更範囲

既存V1・V2の手動パイロットと共通Spotify処理は変更せず、統合スケジューラの呼び出し先を新しい補完エンジンへ変更。独立した複製スクリプトや別台帳は作らない。既存の照合方針、Omny URL形式、列、除外履歴、実行履歴、ロック・リースを維持する。

1. 一度に扱うのは1フィード。コールド取得・XML解析後は `SNAPSHOT_READY` を返し、その実行ではセルを書かない。
2. 抽出済みRSSデータを18,000文字以下の断片に分け、SHA-256付きのマニフェストを最後に公開。CacheServiceの断片は最大約72KB、TTLは6時間。800断片を超えたら停止。早期キャッシュ消失は正常に起こり得るものとして扱う。
3. URL・スナップショットハッシュ・アイテム位置をScript Propertiesに保存。処理途中の同一スナップショットはそのまま使う。キャッシュ欠落時は再取得、内容変更時は位置0から再走査。内容が同じなら位置を維持。
4. 1フィード完了後に次のフィードへ。次巡の古いキャッシュはETag / Last-Modifiedで条件付き取得し、304なら再解析しない。RSSに標準の過去分差分APIはないため、200の場合はその1フィードの全本文を受信する。ネットワークの完全なアイテム差分取得ではない。
5. キャッシュ処理は1回最大200アイテム走査、最大10エピソード補完、開始から120秒を目安とし、書き込み前に余裕を確保。セル単位で確認・書き込み・読み戻しを行う。途中で期限に達したアイテムは再開対象に残す。
6. 実行履歴追記後にチェックポイントを確定。途中失敗で位置が古いままでも、次回は既存値を保持して残りだけ補完する。キャッシュの満了や0件補完を全履歴の完了とみなさない。

## 照合・保護

- GUIDが既存なら一意性を要求。空欄ならOmnyの明示的clip UUIDを要求。タイトルだけ・Spotify URLの存在だけではGUIDを確定しない。
- RSSと台帳の番組名、NFKC正規化タイトル、JST日付が一致すること。RSS内の同一GUID重複は保留。台帳ID、GUID、clipの重複やOmnyリンク間の矛盾を保留。
- GUID・音声URL・概要原文・出演者・Spotify個別URLのみ空欄補完。EP-IDや行は追加・変更しない。既存の音声URL・SpotifyリンクがRSS根拠と矛盾すれば保留。
- 出演者はPodcast Namespaceの明示的 `person role=host/guest` のみ。author/producerや本文からの推測は行わない。Spotifyは当該RSSアイテムの明示的episode URLのみ。根拠がない空欄は残る。
- AM、人間の削除・除外履歴（GUID・EP-ID）を検査。各セルの直前に行の識別情報、除外履歴、空欄・数式を再確認。新規Spotifyリンクの同一実行内重複も防ぐ。概要が数式として解釈されることを防ぐ。
- 既存値は上書きしない。ロックはスクリプト同士の競合を防ぐが、Google Sheets UIでの人間の編集との原子的なcompare-and-setは提供されない。確認と書き込みの極短時間の競合は残るため、本番試験中は台帳の同時編集を避ける。
- 人間が単にセルを空欄化し、AMや削除・除外履歴に意思を記録しなかった場合、元からの欠損とは区別できない。復活禁止は必ず除外として記録する。

## HTTP / Spotify

取得失敗は成功とせず、403など恒久エラーは `STOPPED_HTTP`。429・503は `Retry-After`（秒またはHTTP日付）と指数バックオフの長い方まで待ち、カーソルを進めない。待機のためのsleepは行わず、次回実行で再開。5回失敗で停止。通信例外・XML破損は例外として既存コントローラの連続失敗停止へ渡す。

RSS補完経路ではSpotify APIを呼ばないため、既存の共有Spotify関数のエラー挙動を持ち込まない。追加した `libV2CpSpotifyRead_` は、明示的episode IDと呼び出し元のトークンで検証するための任意の読み取りアダプタ。403・429・503の状態をそのまま返し、200でもID/type/正規URLを検証する。Spotify検索や新規ID発見は実装しない。将来アダプタを使う呼び出し元は返されたretry状態を保存し、VERIFIEDまで境界を進めてはならない。

GASは単一のブロッキングHTTP取得やXML解析を途中で中断できない。今回の構造は全フィード同時取得をなくすが、1フィード単体が最大時間を超える場合まで保証するものではない。既存8分リース、ScriptLock、150秒完了後停止を維持。実タイムアウト後はリース満了前の重複実行を拒否する。トリガーが残っていても恒久エラー後はenabled=falseで無処理。
