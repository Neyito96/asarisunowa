## 既存ダッシュボードと速度の監査

- 既存ダッシュボードの台帳件数6,591、音声あり1,226/なし5,365は台帳と一致。最新履歴表示にはMEDIA TALKパイロットが出る。
- 一方、最終実行日時が古く、直近補完件数/保留件数に数値でなく見出し文字が出る。V3はこの表を無断修復せず、承認後に専用の機械管理表を作り、状態別の集計を提供する。
- V1は候補上限到達でRSS取得を打ち切るがアイテム途中位置を保持しない。旧V2はfetchAllで全RSS/全XML解析後に件数制限するため、件数を減らしても取得負荷が残る。旧統合スケジューラからの重複プレビューも重い。
- PRのV2チェックポイントは1フィードキャッシュを処理。V3はその取得/HTTP/識別子処理を再利用し、フィード別の保存位置と処理交代を追加。大番組の補完完了まで小番組を待たせない。
- V3のキャッシュ断片は22,000文字（UTF-16サロゲートを分割しない）。V2既定18,000文字は維持。全10フィードの断片数・既存V2キャッシュとの競合、早期消失は本番で要計測。消失時は再取得して安全に再開。
