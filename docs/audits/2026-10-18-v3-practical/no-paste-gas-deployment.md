# Phase 6 — Macで反復コピペをしないためのデプロイ方針（2026-10-18）

## 判断

**現行の「GitHubのLibraryV3.js全文をGASに貼る→テスト→貼り直す」手順は撤回する。**
理由：2026-10-17隔離GASは35ファイル（元34+変更2+追加1）で整合性確認済み。一方GitHub作業ブランチのLibraryV3.jsには後続のV3/Phase6修正があり、オンラインのベース18af81aからの差分以外の変更を含む。全文置換や複数回の切り貼りは危険かつ非効率。

## 目標

Macの手作業は「一度だけ接続/承認→保護付き同期コマンド実行→ログ共有」に限定。実行自体は読み取り専用、実シートへの書込は別フェーズで承認。

### 推奨手段A：Workで隔離GASを直接扱う

- Workのブラウザから隔離GASの全ファイルの現行内容を取得し、GitHubの作業ブランチとの差分を検証。
- 35ファイルのファイル名・本文ハッシュ・manifestをバックアップ。差分対象は`LibraryV3.gs`のみ。
- 重複関数・依存関係・旧writer副作用を検査してから、承認済みREAD_ONLY更新を1度だけ反映。
- 保存後に本文を読み戻し、同一ハッシュであることを確認。実行関数`previewLibraryV3MacHandoff()`を手動1回。ログとwrite=0、propertiesWrites=0を確認。
- 異常時はその場で停止・元本文を復元。
- この通常チャットからWorkに自動的に切り替えたり、そのブラウザを操作したりすることはできない。

### 推奨手段B：Mac + clasp（Google Apps Script API）

1. 初回のみNode.jsと`@google/clasp`、Google認証とApps Script APIの有効化を設定する（環境要件は最新公式ドキュメントで確認）。
2. **必ず**隔離スクリプトIDを明示的に指定。`clasp pull`で現行35ファイルを専用ディレクトリに取得し、Gitとハッシュでバックアップ。絶対に本番scriptIdと混同しない。
3. 取得できたオンライン版のハッシュと過去基準`18af81a`の一致性、ファイル数35、依存ファイル名、重複関数を先にチェック。不一致なら無変更停止。
4. 手元の差分検査を通過した**承認済みの1ファイルのみ**を更新し、元の他34ファイルを保持したまま、`clasp push`を1回だけ実行。clasp pushはプロジェクト全体を同期する操作であるため、単独更新と誤解しない。ハッシュ照合に加え既存ファイルが消えないか差分を必ず監査。
5. Apps Script上の対象関数READ_ONLY実行とログ収集。毎回GAS画面で貼り替える必要はない。修正時はGitHubでコード更新、Macでチェック済み同期を再実行。
6. この仕組みを整備せずに、見切りでpushや上書きをしない。復旧は元の35ファイルを完全同期する方法を検証してから行う。

## 成功条件（単一のゲート）

- 接続IDが隔離であることを照合
- オンラインの全35ファイル・manifestがバックアップ済み
- 一致条件とコードテストを通過
- 変更するファイルの内容・依存範囲と実行関数を一度に提示
- READ_ONLYプレビューは0書込、V/W・記事・出演者・Spotify/音源候補のレポートを保存
- 自動でV3 writerを本番化しない。コピー1件保存と新着トリガー切替は別承認

## 注意

- `previewLibraryV3MacHandoff()`自体がSpotify URL・音源到達検証の全機能を集約しているわけではない。Spotify・音源のREAD_ONLYチェックは別の既存関数の結果と統合監査する必要がある。
- **現在のコードは統合保存writerが未完成**。Mac同期の自動化だけで図書館自動収蔵が完成するものではない。
- GitHubのPR/CIで現在の回帰テストが完走した証拠はなく、オンラインGASの稼働は未検証。
