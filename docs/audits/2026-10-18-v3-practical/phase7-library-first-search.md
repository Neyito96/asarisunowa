# Phase 7：新着RSS→図書館ファースト検索（2026-10-18）

## 概要
従来Spotify検索起点の自動更新を、公式RSSの新着候補→GUID・Omny Clip ID・朝日itemidで図書館一意照合→図書館内の出演者・連載・テーマ検索→Spotify URL検証後のプレイリスト反映へ切替える。既存V1/V2の更新を停止せずREAD_ONLY並走から始める。

## 新着の順序
1. 公式RSS取得、GUID・補助アンカー、削除履歴と照合。未一致のみでは新着確定としない。
2. RSS原文・清掃版・出演者役割と出典・関連記事・enclosure音源URLを図書館へ提案。Spotify URLがなければSpotifyへの追加は保留。存在しないURLを生成しない。
3. 図書館で出演者、連載、テーマ、全文の順に検索。ヒットとSpotify反映を分離。削除済みの復活禁止、重複防止、429等のリトライ尊重。
4. Spotify未配信の場合も図書館側候補は保持し、Spotifyリンク到着後の後日照合で反映する。

## 推奨の別タブ（初回は隔離コピーのみ）
- 連載マスター：seriesId,番組,連載名,別名,根拠,承認状態,有効期間。
- エピソード×連載：epId,seriesId,根拠,状態,更新日時。
- テーママスター：themeId,テーマ名,同義語,除外語,親テーマID,公開状態,ルール版。
- エピソード×テーマ：epId,themeId,抽出根拠,RSS原文ハッシュ,信頼度,編集承認,更新日時。
- 検索・プレイリスト候補：epId,対象playlistId,候補種別,一致証拠,Spotify URL,保留理由,最終確認。
- 索引更新状態：番組,取得日時,索引日時,件数,エラー,チェックポイント。
EP-IDは既存台帳の固定キーとし、新しい索引から採番しない。テーマを単なる1セルの自由記述にせず、多対多の関連として保持する。

## 改善アイデア
- 出演者は名前だけでなくpersonId・表記揺れ・役割（MC/ゲスト/取材/制作）と根拠で索引化する。本文登場人物を出演者として自動認定しない。
- 連載は番組と別概念にし、再配信・シリーズ番号の取り違えを防ぐ。
- テーマ候補は同義語辞書＋除外語＋根拠を保持し、機械抽出のみでは非公開。承認済みのみ標準検索へ出す。
- 検索不能をSpotify APIへ即フォールバックしない。まず図書館未登録・Spotify未配信・除外などに分類し、照合対象の候補を残す。
- 図書館検索がSpotify APIの403/429でも動くことを移行条件とする。

## 実装
scripts/library-v3-search-index.mjs と tests/library-v3-search-index.test.mjs を作業ブランチに追加。EP-ID/出演者/連載/テーマのメモリ索引を作成し、削除済み、同一ID重複、未承認テーマ、未確定identityを保護する。結果にはSpotify URLとRSS音源URL・到達性をメタ情報として返し、Spotify API呼出0・Sheet書込0。
V8で出演者・連載・テーマ各1件のスモーク確認済み。Nodeテストランナーと実GAS、実シート接続は未実施。新規タブの実作成・本番検索置換・プレイリスト書込はしていない。

## 移行ゲート
A：既存Spotify検索は維持し、図書館検索候補をREAD_ONLY並走してヒット率差を集計。
B：図書館候補を主にしSpotifyを照合/プレイリスト追加専用にする。
C：7番組で新着漏れ・過剰追加・人間除外の復活がないことを実測し、本番切替は別承認。
