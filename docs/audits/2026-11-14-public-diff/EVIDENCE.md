## 再集計の方法（第三者）
1. **配布物の確認**: `tests.json` の `cleanerBuildSourceSha256` と、監査・マニフェストの「配布物SHA256(本体)」が一致することを確かめます。同じコミットで `node scripts/ledger-v2/build-cleaner-gas.mjs` を実行すれば、同じ値が出ます。
2. **計算式**:
   - 監査・全台帳集計の3式（旧公開＝両方＋旧公開だけ／V2公開候補＝両方＋追加／追加＝分類済みの行）が「一致」であること。
   - 監査・全台帳差分の「区分」を数え直すと、集計と同じ数になること。
3. **採否**: 監査・採否集計の採否案を数え直し、`公開できる数 = 両方にある公開EP + 追加のうち VERIFIED` になること。

## 司令塔が挙げた3点の確認（既存の実装で満たしているもの）
| 点 | 根拠（コード・テスト） |
|---|---|
| 新着0件とフィード取得失敗の区別 | `p25v2FetchFeeds_`：HTTP エラー・例外は `errors`、0件のフィードは `empty`。V2 書込は `errors` があれば `STOP_FEED_ERRORS`、日次 `P25V2_D1` は `empty` でも停止（`FEED_EMPTY`）。正常な新着0は `OK`・`added: 0`。テスト `tests/p25-v2-ingest.test.mjs`「新着0件とフィード取得失敗を区別」 |
| ハッシュ一致と内容の正当性は別に検証 | ハッシュ: `scPreservedRaw_` は原文の SHA256 が一致した行だけを使う（改ざん・取り違えの検出）。内容: 清掃結果は別に SQA（品質監査）で判定し、合格・要確認・失敗・HOLD を V2・清掃詳細に保存。公式ページは canonical の itemid と GUID の一致で判定（`verifyOfficialPage`）。どれも「ハッシュが合う＝内容が正しい」とは扱っていない |
| 音声サイズ・再生時間だけで重複と確定しない | L4 の DUPLICATE は「タイトルが（再）で、同じ番組・同じ基本タイトルの原回が公開済み」（L2 の DUPLICATE候補）であることに加えて、再生時間（±2秒）と音声全体の長さの両方が一致した時だけ。どれか1つでも欠ければ HOLD。同じ GUID の別 EP は GUID（強い識別子）で DUPLICATE |
