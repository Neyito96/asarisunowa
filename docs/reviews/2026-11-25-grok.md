全体の印象（3行）
一人のリスナーが2026年9月からAIを多用して作り始めた非公式サイトとしては、機能の密度と誠実さが突出している。約6,100回の蔵検索と星図分類は公式にない実用価値を提供しているが、入口の情報過多と「田・蔵・宇宙」のメタファーが初めての人を戸惑わせる。持続可能性と権利の扱いへの意識は高く、方針は立派だが、現状はまだ「一人＋有料AI」に大きく依存している。

1. 初めて来たリスナーにとっての分かりやすさ
良い点
	•	上部ナビに「田 入口」「蔵 全回検索」「宇宙 テーマ星図」「星読み 分類投票」「？ 質問」が並び、主要ページへの移動は直感的。
	•	各ページで「非公式・リスナー制作｜情報は最新・正確でない場合があります」と明示している（田のトップ付近）。
	•	蔵は検索窓が目立ち、番組フィルタや件数表示（6,115件など）がすぐわかる。
問題点
	•	「田」「蔵」「宇宙」「星読み」の名前が詩的すぎて、初見では意味が伝わらない。FAQを読まないと「何のサイトか」が分かりにくい。
	•	田のトップは公式プレイリストカードが多数並び、情報量が多くてスクロールが長い。スマホでは特に圧迫感がある。
	•	宇宙ページは読み込み中に「星を集めています…」と出るが、初見では操作方法（ピンチや2本指）がすぐ分からない。
改善案
	•	トップに1〜2行の超簡潔な説明を置く（例：「朝ポキ全回を探して聴くための非公式ガイド。公式ではありません」）。
	•	「田」を「入口」や「ホーム」に寄せるか、ホバー／タップで短い説明を出す。
	•	スマホ向けにカードを縦積み優先にし、最初の画面で「蔵で探す」を最優先にする。
（実際に田・蔵・宇宙・FAQを開いて確認。スマホ実機での詳細操作感は未確認だが、デスクトップ表示から推測可能。）

2. 内容の価値
良い点
	•	蔵：約6,100回をタイトル・出演者・キーワード・番組・日付で検索でき、各回から公式配信先へ直接飛べる。公式サイトにはない横断検索として実用価値が高い。
	•	宇宙：20の大分類による星図可視化と、言葉・地図・関連回の接続は「他にない」体験。分類の確度（人確認／AI高中低）を色帯で示している点も誠実。
	•	プレイリスト案内と「どれ聴く？」診断は、聴き始めのハードルを下げる。
問題点
	•	宇宙は「試験版」と明記されている通り、分類は主にAI（Claude）の試作。確度の低い星が多く、まだ「正確な地図」ではない。
	•	蔵の検索結果の詳細表示や、関連回の根拠の見せ方はまだ改善の余地がある（推測：詳細ページの読み込みが重い可能性）。
改善案
	•	蔵を「一番使ってほしい機能」として前面に出す。
	•	宇宙は「見て楽しむ・投票で育てる」位置づけを明確にし、検索の代替にはしないとFAQで強調する。
（蔵・宇宙を実際に開き、件数や分類リストを確認。関連回の詳細クリックまでは深く掘っていない。）

3. コミュニティとしての参加しやすさ
良い点
	•	「みんなで星読み」は登録なしで投票可能。票がすぐに反映される仕組みは参加ハードルが低い。
	•	FAQに「気軽な感想はDiscord、開発アイデアはGitHub Issue」と明確に分けて案内している。
	•	Issue駆動で進捗が公開され、#493で持続可能性を議論している。
問題点
	•	投票以外の投稿手段（感想やおすすめ）がサイト内にほぼない。Discordへの導線はあるが、サイト単体では「見るだけ」になりやすい。
	•	GitHub Issueは開発者向けで、一般リスナーにはハードルが高い。
改善案
	•	蔵や宇宙の各回に「この回について一言」程度の軽い投稿欄（またはDiscordへの直接リンク）を置く。
	•	「星読みで投票した人へ、次の一歩」を軽く案内する。
（minnaページとFAQを確認。実際の投票動作は未実施。）

4. 信頼性と正確さ
良い点
	•	非公式であることを複数箇所で明示。
	•	分類に「人確認」「AI確度高中低」の色分けを用意し、FAQで「正しさの印ではない」と説明している。
	•	データ更新日時や件数を表示。
問題点
	•	AI分類の誤りが残っている可能性が高い（特に「ふちの星」やミミマチ星群）。
	•	「情報は最新・正確でない場合があります」と書いているが、具体的な誤り事例や報告方法がもっと目立つとよい。
改善案
	•	各分類ページや星詳細に「この分類がおかしいと思ったら」ボタンを常時表示。
	•	データソース（公式情報を基に編集）を蔵のフッターでも繰り返す。

5. 権利と倫理
良い点
	•	題名・概要欄・音声は権利者のもので対象外と明記。コードはMIT、自作データはCC BY 4.0。
	•	画像は「識別・案内目的で引用」と出典方針を書いている。
	•	AI利用（Claudeによる分類試作）をFAQで開示。
	•	個人情報をサーバーに残さない方針（蔵書は端末内のみなど）。
問題点
	•	番組画像の引用が「出典元が分かる形」とあるが、実際の表示でクレジットが十分目立つかは要確認。
	•	概要欄テキストを検索用JSONに含めている点は、権利上グレーになり得る（公式が許容しているかは不明）。
改善案
	•	画像引用のクレジットをさらに明確に。
	•	権利方針をopenページだけでなく、蔵・宇宙のフッターにも短く置く。
（openページとFAQを確認。実際の画像クレジット表示はスクリーンショットから一部確認。）

6. 持続可能性
良い点
	•	Issue #493で「個人依存を減らす」「専用アカウントへ引っ越し」「鍵の分け持ち」「手引き化」を具体的に進めている。
	•	自動処理（GAS＋GitHub Actions）を多用し、日常更新の人的負荷を下げようとしている。
	•	ライセンスを明確にして引き継ぎ可能にしている。
問題点
	•	現状はまだ「ネジート＋有料AI」への依存が大きい（FAQでも認めている）。
	•	GoogleスプレッドシートやGASの鍵管理が個人に集中している可能性が高い。
	•	費用（有料AI）の見通しが「早めに抜けたい」段階。
改善案
	•	手引き（運用マニュアル）を最優先で公開する。
	•	複数人での鍵共有と、最低限の監視体制を急ぐ。
（FAQとGitHub Issue #493を確認。実際のGASコードの詳細は未深掘り。）

7. コードと運用の健全さ
良い点
	•	GitHubで公開、Issue駆動、testsフォルダやdocsがある。
	•	静的サイト（GitHub Pages）で運用コストが低い。
	•	本番反映前に人の確認を入れる運用を明記。
問題点
	•	リポジトリがかなり大きく複雑（Next.js＋多数のフォルダ）。素人が引き継ぐのは容易ではない。
	•	自動処理の壊れやすさや、秘密情報の扱いの詳細は外部から完全には見えにくい。
	•	スター0・フォーク0の状態で、コミュニティのコード貢献はまだほとんどない。
改善案
	•	「最低限これだけ分かれば回せる」短い運用ガイドをdocsに置く。
	•	重要な自動処理の監視と、失敗時の通知を強化する。
（GitHubリポジトリの構成とREADME、Issueを確認。コードの詳細レビューや秘密情報の有無は表面しか見ていない。）

8. デザイン
良い点
	•	蔵の和紙・蔵印モチーフ、宇宙の暗い星図は世界観が一貫していて美しい。
	•	色分けやカードデザインに統一感がある。
問題点
	•	田は情報の詰め込みが多く、余白が少ない。特にスマホで「どこから見ればいいか」が分かりにくい。
	•	ページ間でヘッダーのトーンが少し異なる（田は明るく、宇宙は暗い）。
改善案
	•	田を「案内のハブ」に絞り、詳細は蔵・宇宙に任せる。
	•	共通のシンプルなヘッダー・フッターを全ページで揃える。

今すぐ直すべきこと トップ5（影響大・手間相対的に小）
	1	トップページ（田）の説明を1〜2行追加し、「非公式の全回検索・案内サイト」であることを最初に伝える → 初見離脱を大きく減らせる。
	2	「田・蔵・宇宙」のメタファーに短い注釈を付ける（ナビやFAQの冒頭） → 分かりにくさの最大要因を解消。
	3	蔵を入口からもっと前面に出す（スマホでも一番目立つ位置に） → 実際に役立つ機能をすぐに使ってもらう。
	4	分類の誤り報告・星読みへの導線を、宇宙の各星詳細で常に目立つようにする → 信頼性とコミュニティ参加を同時に強化。
	5	運用の手引き（最低限の更新手順・鍵の場所・失敗時の対応）をdocsに公開する → 持続可能性の最大のボトルネックを少しでも減らす。
全体として、熱量と誠実さは本物で、公式にない価値をすでに提供できている。一方で「初めての人への優しさ」と「一人依存からの脱却」が、今いちばん重要な課題です。
