# テーマ別プレイリストと投稿者選択UI(2026-11-09)

## 投稿者の操作の流れ
1. 既存の自動更新フォームで「テーマ」を選ぶ。
2. 「蔵から回を選ぶ」で検索し、一覧から複数選択する(最大100件。EP-00028 は選べない)。
3. 送信すると、申請シートの10列目に選択した EP-ID が保存される(依頼。Spotify には何も追加されない)。
4. サーバー側が蔵と照合する: 蔵にある回 / GUID あり / Spotify ID が正しい / AM 列「人間除外」でない / 「削除・除外履歴」にない / 管理者HOLDでない。通らない回は理由つきで却下され、申請は保存されない。
5. 管理者がテーマ別管理シートを有効化すると、通った回が「未確認 / 投稿者選択」の行になる。既存の書き込み処理は判定=採用の行しか追加しないため、**管理者が判定を「採用」に変えるまで Spotify には何も追加されない**(独立した管理者承認)。

## テーマ別 1 管理シートの構造(1プレイリスト = 1シート、14列)
ルールキー / エピソードID(Spotify ID)/ 公開日 / 番組名 / エピソード名 / 一致キーワード / 概要抜粋 / Spotify URL / 判定(未確認・採用・除外)/ 確認日時 / 追加日時 / エラー / 判定元 / AI理由

状態は列の組合せで区別する(`themeV3RowStateV1_`):
| 状態 | 条件 |
| --- | --- |
| 手動選択(採用待ち) | 判定=未確認、判定元=投稿者選択 |
| 管理者採用 | 判定=採用(投稿者選択の行を管理者が採用、または判定元=人間) |
| 新着候補 | 判定=採用、判定元=AUTO新着 |
| Spotify追加済み | 追加日時あり |
| 除外 | 判定=除外(人間の除外は上書きしない) |

## 二重投稿・除外の扱い
- 管理シートがあるプレイリストは P25 の所有者にできない(`THEME_MANAGED_BY_V3`)。書き込む系統は常に1つ。
- すでにシートにある回(除外を含む)は取り込みで上書きしない。手動削除は既存の墓石(追加日時あり・Spotifyに無い)で再追加されない。
- EP-00028 は選択画面にも出ず、サーバー側でも `ADMIN_HOLD` で却下される。

注: 既存のAUTO初稿(キーワード一致を判定=採用で入れる従来の仕様)は今回変更していません。投稿者選択だけが未確認で入ります。
