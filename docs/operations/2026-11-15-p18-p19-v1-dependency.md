# P18・P19 の旧本番（V1）依存箇所（2026-11-15 実GAS読み取り）

実GAS「朝ポキ｜本番ロボGAS」（17dvPB…）のソースをエディタ上で読んで確認（保存・実行・トリガー変更なし）。ソース本文はURLを含むためリポジトリに写していない。構造のみ記録。

## P18（P18PlatformUrlBot20261103.gs, `p18-platform-worker-20261103.1`）
- 読む: `P16_RECOVERY_SHEET_ID_`（＝旧本番 V1 1lLgLz…）の「エピソード台帳」と「P15_PLATFORM_CANDIDATES」。
- 照合: 候補URLを `P15_PLATFORMS.resolve()` で確認し、GUID・音声・番組/配信日/再生時間のどれかが公式行と一致したときだけ VERIFIED（題名の似ていることは証拠にしない）。
- 書く: `PHASE15_INTEGRATED.writeRow(ss, sh, 行番号, 行, [{col: 列番号, value: URL}])` で **V1 の列番号固定**（11 LISTEN／12 Spotify／13 Apple／41 Amazon／42 Pocket Casts／43 Pody）。1回最大3件・最大40行・6ページ。
- 門: スクリプトプロパティ `P18_URL_ENABLED` が YES のときだけ書く（P18_WRITE_GATE_CLOSED）。
## P19（P19PlatformDiscovery20261103.gs）
- 読む: V1 の「配信先URL」（番組ごとの一覧ページ）と「エピソード台帳」（URLが空の行を探す）、既存の「P15_PLATFORM_CANDIDATES」。
- 書く: V1 の「P15_PLATFORM_CANDIDATES」（列 SHOW / SERVICE / LABEL / URL / DISCOVERY_URL）。**GUIDは持たない**。
## V1 依存のまとめ（移行で置き換える所）
1. スプレッドシートID（V1固定） 2. 「エピソード台帳」の列番号固定 3. 書込関数 writeRow（V1の監査シート前提） 4. 候補シート・配信先URL シートが V1 内 5. URLが空の行の探し方が V1 の行（V1 は 2026-11-14 から新着が増えない）

## 移行の方針（PR #306 の照合ロジックを使う）
- 入口 `v2RowsFromSheet`（V2を見出し名で読む）・`candidatesFromP15Sheet`（番組＋題名1件一致でGUIDを付ける）を追加。題名一致だけでは `identityVerified=false` のため提案しない（P15_PLATFORMS.resolve の VERIFIED だけが true にする）。
- 書込は V2 の見出し名で列を引き、空欄だけ。既存URLは変えない。
- 本番ロボGASに橋渡しファイルを置く作業は本番GASプロジェクトの変更に当たるため、承認後に行う。まず COPY の V2 台帳コピーを書き先にした予行（読むだけ→COPYへ少数）で、変更0・誤対応0・再実行で追加0 を確かめる。
- 旧 P18 の書込門（P18_URL_ENABLED）を閉じてから新しい方を動かし、V1・V2 の並行書込を避ける。Spotify プレイリスト同期・V2 日次収蔵には触れない。
