## ② 統合実行計画（依存関係の順）

```
A 台帳正本（V2）── B 概要・人物・関連記事 ──┐
        │                                  ├── E1 V2 → 公開データ変換 ── E2 公開サイト反映 ── E3 監視
        └── C 公式URL・各サービス ──────────┤
D 新着の毎日の自動収蔵（A〜C を毎日まわす）─┘
```

1. **最大の阻害要因は「V2 の成果が公開サイトに入る経路がないこと」です。** A〜C をいくら直しても、公開サイトは10/22のままです。B・C の実機検証と並行して、E1（V2 → 公開データの変換）を作ります。
2. COPY と V2 の境界:
   - COPY の統合台帳は古いので、試験の材料にしません（関連記事で実測済み）。
   - 試験は「V2 を読んで、COPY の試験シートに書く」方式に統一します。
   - V2 への書込はすべて承認ボタンの後だけです。
3. GAS を実行する地点（管理人）:
   - B: 関連記事索引の確認
   - C: U1・U2
   - D: D1/D2 の COPY 試験 → 承認 → D8
   - E2: 公開の承認
