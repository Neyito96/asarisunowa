# Spotify 個別URL 空欄の調査と補完（2026-11-18）

## 症状
蔵の EP-06700〜06751（52件）で Spotify の個別URLが空。V2・統合台帳の Spotify 欄も EP-06692 以降が空。

## 原因（止まっていた工程）
- 以前の新着取込（V2収蔵ボット P15）は取込時に Spotify の回URLも入れていた（P15_RUNS の MEDIA 欄）。P15 の最終実行は 2026-11-10。
- その後の新着は清掃ロボの巡回（P28: JUDGE/CLEAN/AMZ/PDC/PD/PC/NEW/LS/AP）が取り込んでいるが、**巡回に Spotify の仕事が無かった**。
- 清掃ロボには Spotify API の認証情報が無く、Spotify を調べる手段そのものが無かった。
- そのため EP-06692 以降は誰も Spotify 欄を埋めていない（エラーではなく「担当が無い」状態）。

## 直したこと
1. GitHub Actions `spotify-new.yml`（毎日 06:40・12:40 JST）
   - 7番組の Spotify 番組ページ（ログイン・APIキー不要）から回のURL・題名・配信日・長さを取得 → `docs/spotify/latest.json`
   - V2・公開台帳（読むだけ）と照合 → 確定分だけ `docs/spotify/matches.json`（`scripts/spotify/match.mjs`）
2. 照合の確定条件（緩めない）: Spotify番組IDが一致 / 題名が同じ（全角半角・空白だけ揃える）でその番組の行が1つ / 配信日が−1〜+1日 / 長さの差5秒以内 / 1対1 / 台帳に値がある行は対象外
   - 例外: 広告の差し込みで Spotify 版が毎回ほぼ同じ秒数短い番組（ニュースの学校 約44秒）。題名・日付一致が5回以上・差が0〜90秒で中央値±8秒に揃う番組だけ、中央値±8秒の回を確定。
3. 清掃ロボの巡回に SPT（P32）を追加（Draft PR #343 のブランチ）: `matches.json` の確定分を読み、番組・題名が台帳と同じで Spotify 欄が空の行にだけ書く（読み戻し・停止旗・取消は既存の P27 の仕組み）。
