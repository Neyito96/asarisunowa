# P27 配信先URLロボ 手順書（管理人向け）2026-11-17

対象プロジェクト: 清掃ロボ（COPY/V2作業用 GAS、`1C3kV3rMUZKg8Yyoogbd98plmCbKfhwoiwIo2RlQtBHlBHJvutDcTlEN8`）。本番ロボ（P26）とは別物で、P26 には触れていない。

## 共通の約束
- 関数名の最後に `_READ_ONLY` が付く関数は、V2 を読むだけ。結果は COPY のシートにだけ書く。
- 名前に `COPY試験` が付く関数は、COPY にある台帳の写しにだけ書く。最大10件を書いて、読み戻し → 再実行で差分0 → 取消で元に戻す、まで1回で行う。結果が `PASS` なら合格。
- V2 に書く関数（`P27_PC_5`・`P27_PD_5`）は、コードの `P27_V2_WRITE_ENABLED_ = false` で止めてある。押しても `DISABLED` と出るだけで、何も起きない。
- トリガー（自動実行）は設置していない。

## 毎日の運用（新着の回を7サービスへ）★いちばん大事
新着の回を、7サービスの回ごとのページと自動で結びつける流れです。過去回の穴埋めより、こちらを優先します。

| 順 | 誰が | 何をする | 期待するログ |
|---|---|---|---|
| 1 | Claude | Chrome で Amazon Music の各番組ページを1回ずつ開き（1日最大8ページ）、新着一覧の回のリンク・日付・題名・長さを COPY「P27・Amazon証拠」に書く。相対表示（「3日前」など）は取得時刻から日付に直す | ― |
| 2 | 管理人 | `P27_NEW_1_新着照合_READ_ONLY` を押す（読むだけ） | `status: OK`。サービスごとの VERIFIED／HOLD／UNAVAILABLE の件数と、書ける件数（writable） |
| 3 | 管理人（承認後） | `P27_NEW_0_承認_新着V2反映` → `P27_NEW_5_V2反映_承認後` | 今は `DISABLED`（V2書込はコードで無効） |
| 戻すとき | 管理人 | `P27_NEW_7_直前の新着反映を戻す`（列をまたいで一度に戻す） | `status: OK` |

- 対象は、配信日時が14日以内の回。スクリプトのプロパティ `P27_NEW_DAYS` で日数を変えられる。
- 結果は COPY に書かれる。「P27・新着照合」が1回×7サービスの表、「P27・Amazon証拠待ち」が Chrome で見る必要のある回の一覧。
- 動作確認は `P27_NEW_2_COPY試験`（COPY の写しだけ・合計10件）で行う。

## Amazon Music の証拠の集め方（AI が行う。管理人の入力は前提にしない）
1. 管理人の承認を受けた件数（1回10件まで）だけ、Claude が Chrome で Amazon Music を開く。人と同じ画面で回の題名を検索する。
2. 画面に出た回のリンク、番組名、日付、題名、長さを、COPY「P27・Amazon証拠」に1行ずつ書く。リンクは末尾の飾り文字を外すだけで、番号は変えない。
3. `P27_AM_1` を押すと照合する。`VERIFIED` になるのは、番組ID、題名、日付（UTCの日）、長さがすべて合ったものだけ。似た題名や再放送の別番組は `CANDIDATE` か `HOLD` になる。
4. 大量巡回はしない。1回10件まで・1件1検索に限り、接続が不安定なら止める。

## 異常のときの対応
1. 読み戻しが一致しないと停止旗が立ち、それ以降の書込は止まる。
2. `P27_PC_8_未完了の確認` で状況を見る。
3. `P27_PC_7_直前の反映を戻す` を押す。どの列でも、直前に反映したものを戻す。反映の後に人が直したセルは戻さない。
4. 原因を確かめてから `P27_PC_9_停止解除` を押す。
5. 履歴は COPY「P27・反映履歴」に残る（列名つき）。

## まだ承認されていないこと（押しても動かない・または実行しない）
- V2 への反映（Pocket Casts・Pody・Amazon）
- 本番ロボへの配置
- 新着時の自動運転（トリガー）
- YouTube Data API の有効化

## 2026-11-17 司令塔追加：V2反映前の受入ゲート（PR #314）

**本番V2への書込・トリガーは依然として禁止**。現在のコードでは `P27_V2_WRITE_ENABLED_ = false`。PRをmainへマージすることも、本番GASへ配置することも、この節だけでは許可しない。

1. 最新PR #314の `tests/p27-new-safety-gates.test.mjs` を `node --test tests/p27-new-safety-gates.test.mjs` で実行し、テスト総数とPASS/FAILをIssue #287に貼る。既存P27テストも実行し、従来からの失敗と新規失敗を区別。
2. 清掃ロボの**COPYのみ**に最新版コードを配置する場合は、配置前のGASソース/スクリプトプロパティ/シートをバックアップし、配置先のスクリプトIDとコミットを記録。管理人の事前許可なしに既存運用中のGASを上書きしない。
3. COPY実機で `P27_NEW_1_新着照合_READ_ONLY` → `P27_NEW_2_COPY試験`。書込/読戻し/再実行差分0/取消復元/他セル不変のログを保存。
4. 承認ハッシュの改変、複数列途中失敗、UNDO失敗・再試行、手動編集保護、履歴欠損、同時実行、上限到達を**本番V2には触れず**模擬/COPYで試験。各ケースの前後の履歴と停止状態を報告。試験用にV2書込フラグをtrueへ変更してはならない。
5. 本番承認前に、新着候補の **EP-ID・番組・列・URL・根拠・旧値** と、HOLD/競合/除外の一覧を固定。承認後に取得結果が変われば `STOP_PLAN_CHANGED` で再承認する。
6. まず少数件を承認して反映するには、**現在の一括 `P27_NEW_5` に少数件選択機能がない**ため、EP-ID/列を明示した限定承認・限定書込の機能を別途実装してCOPYで検証すること。現状の関数を「数件だけ書く」と説明して実行してはならない。
7. Amazonの残り6番組はREAD_ONLYで番組IDを調査。EP-06678の「ポリレビ #19」対「#18」はHOLD。公式RSS/GUID/音声/日時で確認するまでAmazon URLを採用しない。

**判定**：このゲートの試験証跡が揃い、管理人が対象EPと件数を確認して初めてV2反映の可否を判断する。
