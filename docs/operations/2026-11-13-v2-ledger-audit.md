## 2. 公式個別URL（統合台帳J列）の欠落【最優先】
- **実測**:
  - EP-06698〜EP-06725 の28話は J列が空です。L列（旧元ページURL）には Omny のURLが入っています。
  - ニュースの学校の回（EP-06684・06690・06706 など）は J列も L列も空です。
  - 最新側の EP-00001〜00003 も J列は空です。つまり「06698以降だけ」の問題ではありません。
  - 一方、EP-03139 などの古い回には `https://www.asahi.com/special/podcasts/item/?itemid=<GUID>` が入っています。
- **原因（コードで確認）**:
  - 新着収蔵（`P25V2IngestAdapter.js`）は、RSS の `<link>`（Omny）を「旧元ページURL」に入れます。「公式個別URL」は常に空で追加します（290行目の `officialUrl: ''`）。
  - 公式個別URLを確かめて埋める工程が、収蔵の後にありませんでした。
  - **このままでは、明日以降の新着も同じく空になります。**
- **列のずれ（実測）**: EP-06679〜06694（未判定の16話）は、J列（公式個別URL）に **Omny のURL** が入っています。L列と同じ値です。朝日の個別ページではありません。
  - L1 は「公式個別URLの形が違う」として一覧に出します。
  - **上書きはしません。** 既存の値は保護します。直すかどうかは人が判断してください。
- **補完の方法**:
  1. `U1_公式URL_確認`（読むだけ）で、空欄かつ GUID がある行の公式ページを実際に取得します。
  2. HTTP 200 で、canonical の itemid が GUID と一致したものだけを「確認済み」にします。
     - 404 は NOT_FOUND
     - 不一致や canonical なしは HOLD
     - 通信の失敗は ERROR（次回もう一度確かめる）
  3. `U2_公式URL補完_V2` は承認後に、**今も空欄で GUID が同じ行にだけ** 書きます。履歴を先に残し、書いた後に読み戻します。
  4. 取消は `U9`（今もその値のセルだけ空に戻します）。
  - ニュースの学校に朝日の個別ページがあるかどうかは、**L1/U1 の実行結果で確定** します（推測しません）。
- **新着への接続**: 承認後は、日次 `D2` が U1（2分まで）→ U2 を毎日行います。収蔵ロボそのものは変えていません。

## 5. 関連記事の見出し・URL・改行
- **新しいシート `V2・関連記事索引`**（1記事1行）を作ります。列は EP-ID、番号、見出し、URL、リンク（HYPERLINK 式）、出典、元URL（原文の表記）です。
- **見出しの出どころ**:
  - 保全済みの概要原文（公式RSS）から清掃器が取り出したものを優先します。
  - 原文に見出しが無い記事、または台帳の関連記事URL列にだけあるURLは「未取得」とします。見出しを作ることはしません。
- **URLの保全**: 台帳の URL と、原文の表記（`?iref=omny` 付き）の両方を残します。
- **統合台帳の関連記事URL列は変えません。** 1つのセルに複数のリンクと見出しを入れる表示は、Sheets の式やリッチテキストでは管理しにくく、検索もしにくいため、別シートにしました。
- 見出しの文字列検索は、このシートで「Ctrl+F」かフィルタで行えます。

## 9. 管理人の操作手順
すべて **GAS プロジェクト「概要欄清掃ロボ（Issue #308・COPY/V2作業用）」** で行います。上の関数選択欄で関数を選び、「実行」を押してください。

1. `L1_台帳総合監査` → ログに `"status": "OK"`、`officialUrlEmpty`、`gapFrom`、`sdgs` の件数が出ます。COPY に「監査・…」シートができます。
2. `U1T_公式URL_確認_試験20件` → `result` に VERIFIED／NOT_FOUND／HOLD の件数が出ます（20件だけ）。
3. `U1_公式URL_確認` → `PARTIAL_RESUME_NEEDED` なら、もう一度押します。`OK` になるまで続けます。
4. `U2_公式URL補完_COPY` → `written` が件数です。もう一度押して `OK_NO_CHANGE` になることを確認します。
5. （承認後）`U0_承認_公式URL補完V2` → `U2_公式URL補完_V2` → `OK` と `readbackMismatch: 0`。もう一度押して `OK_NO_CHANGE` を確認します。
6. `R1_関連記事索引_予行` → `DRYRUN_OK`。`withHeadline`／`headlineNotFetched` の件数が出ます。
7. `R2_関連記事索引_COPY作成` → `OK`。もう一度押して `OK_NO_CHANGE` を確認します。
8. （承認後）`R0_承認_関連記事索引V2` → `R3_関連記事索引_V2作成` → `OK`
9. 最後に `X1_公開台帳_点検` → `PUBLIC_OK`

## 11. 関連記事索引の差分監査と修正（2026-11-13 22:23 指令・LA-1.1）

### 11.1 R1 と R2 の差（234行・3EP）
- R1 は **V2 の統合台帳**、R2 は **COPY の統合台帳** の「関連記事URL」列を材料にしています。概要原文は、どちらも V2・収蔵詳細の保全原文です。
- 管理人の実行結果では、見出しありの件数が両方とも 17,725 で同じでした。違うのは「未取得」の件数だけです（R2 1,888 − R1 1,654 ＝ 234）。
  - したがって、**234行はすべて、台帳の関連記事URL列だけから来た行（出典＝統合台帳・既存値）** です。
  - 3EP は、COPY の台帳にだけ関連記事URLがある話です。
- EP-ID と記事URL の一覧は、`R4_関連記事索引_V2とCOPYの差`（読むだけ）が COPY の「関連記事索引_差分」に出します。列は 側・EP-ID・記事URL・見出し・出典・V2 と COPY それぞれの台帳の値です。
  - Claude の側では Sheets に接続できず、COPY を読めなかったため、**一覧はまだ取り出していません（未実行）**。

### 11.2 見つかった重複（R1・R2 の両方にあった）
- 台帳の関連記事URL列には `?iref=omny` や `?ref=omny`、書き損じの `?irefomny` が付いたURLが多く入っています。原文から清掃したURLには、これが付いていません。
- そのため、**同じ記事が「見出しあり」1行と「未取得」1行の2行に重なっていました。**
- 手元の V2 の写しで数えると、R1 相当の 19,382行のうち **約1,468行がこの重複** でした。
- 修正: `articleKey` で、追跡用の付け足し（iref／ref=omny／utm_*／cid）と `#` 以降だけを外して照合します。
  - 原文と台帳で同じ記事なら1行にまとめ、台帳側の表記は「元URL」欄に `台帳: …` として残します（URLは消しません）。
  - `rensai/list.html?id=` のように、`?` で記事が分かれるURLは別の記事として残します。
- 修正後（手元の V2 の写しでの推計）: 約17,913行・5,965EP・未取得 約189・台帳だけの行 64。**実際の件数は管理人の R1/R2 の実行で確定します。**

### 11.3 再実行で changed:true が続いた原因
- EP-04536 の見出し `'ケヅレー一家'でビブリオバトル…` は、先頭が `'` です。Sheets は先頭の `'` を「文字列の印」として消すため、読み戻すと1文字短くなり、毎回「違う」と判定していました。
- 読み戻しの検査は EP-ID と URL しか見ていなかったので、`readbackMismatch: 0` のままでした。
- 修正:
  - 書く時は、先頭が `'` なら `'` をもう1つ付けます（`sheetText`）。表示は原文どおりになります。
  - 差分判定と読み戻しは、表示どおりの値で6列（リンク式の列以外）をすべて比べます。
  - 違いがあれば、最初の10件の行・EP・列・前後の値を `changeExamples`／`readbackExamples` に出します。
