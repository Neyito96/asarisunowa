## 2. 採番の最終設計（実装済み eebac1f）
- 新しい EP-ID を振るのは V2 だけ。V2 の予約は V2各台帳＋V1（読むだけ）。**COPY は数えない・引き継がない**。
- COPY の試験はCOPY内だけで重複を避ける（V1+V2+COPY を数える）。本番番号は消費しない。
- V1 の EP-ID は「元EP-ID」列（AD）と `監査・EP-ID対応表` に残す。
- 同一GUIDの二重収蔵は GUID照合＋LockService で防ぐ。V1 が読めなければ止まる（移行完了まで維持）。

## 3. 切替手順（すべて管理人承認後）
1. V2 DRYRUN（`P25V2_V2_2_DRYRUN`）で候補と予定番号を確認（現在: 8件 EP-06726〜06733、元EP-ID 06703〜06710）。
2. V2 へ書込（`P25V2_V2_3_WRITE_BATCH`）→ `P25V2_V2_4_VERIFY`。
3. V2 の日次収蔵トリガー（D1）を設置。**V1 を止める前に** 1回以上 V2 で収蔵が成功することを確認（重なり期間はGUID照合で二重にならない）。
4. V1 の `p15AutonomousTick` を停止。
5. 停止点の差分確認: 停止時刻以降に V1 にだけある GUID が 0 件であること（`P25V2_0_採番点検` と V2 DRYRUN で、V1にあってV2にないGUIDを確認）。
6. 数日並走観察後、V1 は読むだけの保管庫に。

## 4. 取りこぼしゼロの考え方
V2 の収蔵は RSS の全件（直近分）を毎回 GUID で照合するので、V1 停止〜V2 稼働の間に出た回も次の V2 実行で拾える。V2 を先に動かし、V1 を後で止めるため空白期間は生じない。

## 5. 戻し方
- V1 再開: トリガーを再設置（または `P15_WRITES_ENABLED` を戻す）。
- V2 側の誤収蔵: 追記のみ・採番履歴つきなので該当行を特定して取消（既存の取消手順）。
- V2 停止: D1 トリガー削除（停止旗あり）。
