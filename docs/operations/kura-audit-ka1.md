# 蔵・台帳 監査の押し方（KA-1／READ_ONLY）

場所: 既存の COPY 清掃GAS（1C3kV…EN8）。新規プロジェクトは作らない。全部 COPY の監査シートに書くだけで、本番V2・Spotify・蔵は変わらない。

| 順 | 押す関数 | 何が分かるか | 既存/新規 |
|---|---|---|---|
| 1 | `HA_2_HOLD監査_全件` | 概要HOLD 244話の EP-ID・原因・自動修復可否（HOLD監査・明細/集計） | 既存 HA-3 |
| 2 | `KA_0_蔵台帳_総合監査_READ_ONLY` | 出演者・関連記事・再配信・台帳差分(V2公開−蔵)・Spotify候補（蔵監査・*） | 新規（このPR） |
| 3 | `C1_出演者_予行` | 出演者の清掃案（根拠つき）を COPY に予行 | 既存 SC4 |
| 4 | `L1_台帳総合監査` | 台帳全体の整合を再確認 | 既存 SC4 |

- もう一度押しても同じ結果（シートを毎回まるごと書き直す＝差分0）。列が見つからない・取得失敗時は例外で停止し、何も書かない。
- 概要の修復: HOLD監査で「自動修復可」の回だけ COPY の清掃版で確認 → 管理人承認 → 既存 `library-v2-sync` で反映（原文・手動保護508話は同期側で保護済み）。
- 再配信: 「判定=HOLD」は同一性未確定。原本は削除しない。
- Spotify: `蔵監査・Spotify候補` を起点に、本番GASの既存 `previewApprovedThemeCandidates_` → 承認 → `addApprovedThemeCandidatesToSpotify_`（読み戻しつき）。Spotifyの全番組再検索はしない。
- ロールバック: 監査シートは COPY のみ。不要なら「蔵監査・*」タブを削除するだけ。
