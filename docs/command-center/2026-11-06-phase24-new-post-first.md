## 現状の技術的障害
- 実機Spotify所属照合は17/17件まで到達：蔵の候補15件は既存17件に含まれ、Spotify未登録候補0。
- 一方で蔵の連載所属に偽陰性（EP-03752のタイトル差）と未収蔵疑い（#15）があり、**蔵だけの結果0は新着0の保証ではない**。
- 正本 `AutoUpdateAutomationV1.js` の `runAutoUpdateAutomationV1` は4時台の日次管理が想定され、`syncRecentManagedAutoPlaylistV1_` は各Spotify showの最新20件APIを読む。これが旧来のSpotify起点の経路。新方式を動かすために、日次トリガーを二重に作らない。
- 現在のオンラインGASで実稼働しているトリガー/コードは差分確認待ち。GitHub上の予定を本番稼働実績と誤認しない。

## 新着エピソード処理の理想的なパイプライン
1. 公式RSS/Megaphone/Omny収蔵 → GUID・EP-ID一意性検査 → 台帳 A:X、公式根拠、L列Spotify URLを補完。
2. 増分検知（前回正常収蔵時刻／確認済みのEP-ID・GUID集合）。タイトル変更、遡及収蔵も差分として扱い、日付だけで新着判定しない。
3. 台帳から連載／出演者／テーマ候補を生成（人物とテーマはレビュー必須）。
4. Spotify**対象プレイリストの所属だけ**を取得。追加済みならスキップ。未登録なら二重追加防止、人間削除・保留・アカウント編集権限を確認。
5. シートとSpotifyの増分更新は管理人の明示承認後に実装/有効化。2xxだけで成功扱いせず、Spotify側のmembership読み戻しを行い、部分失敗はHOLDとする。
6. 成否・対象EP-ID・処理理由・確認時刻・新着未収蔵・429/403/404を記録。差分があれば通知。蔵更新が止まった場合には「異常なし」とせず「未確認」と出す。
