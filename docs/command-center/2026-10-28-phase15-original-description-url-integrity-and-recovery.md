# Phase15｜最優先：概要原文の完全性と関連記事URLの復元監査
日付 2026-10-28。司令塔指令。ユーザーの現物指摘：V列「概要原文」に関連記事URLが残らない例と、他列にURLが分離された例が混在する。これは清掃品質以前に取得・収蔵時のデータ完全性に関わる。

## 原則
1. V列「概要原文」は、取得元の公式RSS/JSONに実際に含まれていた説明文（HTML、関連記事タイトル、URL、出演者、イベント告知、改行を含む）を**原文のまま**保存する。W列の清掃や、ACなどへの情報抽出を理由にVからURLを抜かない。既存Vを無条件で書き換えない。
2. W列は、エピソード固有の本文・必要な収録日・【関連記事】見出し・**対応する記事タイトルとURL**・LF改行を保持し、出演者一覧・宣伝・イベント申込・番組共通フッターを落とす。関連記事URLのACなど別セルへの複製は補助索引であり、W/Vの代わりではない。
3. URLがない理由を次の状態で分類する：A 原文取得段階でURL脱落、B 現行公式原文にもURL自体なし、C 別列にURLだけ存在し原文との対応未確定、D リンク付きHTMLを抽出した際hrefが落ちた、E 公式URL検証済みで復元可能。元の公開資料がもともとURLなしなら**原文Vに後から捏造追記しない**。復元に必要なら公式再取得結果を別に保存し、修復したVへ差し替える場合も旧Vを退避・差分・出典を明示する。
4. 特定の参考例：EP-00006〜00009は現WにURL、現Vにタイトルしかないとの報告。EP-00004/00010/00011はURL対応がHOLD。EP-00023は出演者セクション後ろに関連記事。EP-00001は関連記事内にニュースレター案内混在。これらをソース原本／現V／現W／AC等と対比して根本原因を確定する。
5. HTML anchor のhrefと可視文字列を別々に保持して、記事タイトル ↔ URLを同じHTML要素または公式構造から結び付ける。件数一致や単純な順番でURLを推測しない。未確定は保留。
6. **713行目以降の大量補填は品質是正まで停止**。EP-00001〜00030の比較監査で（元の公式説明の取得成否、V原文一致、URL総数、記事ペア検証数、W関連記事欠落数）を報告。まず実データの再取得経路を実装・検証し、復旧できる欠損から実際に修正する。URLの紐付けに失敗しても、出典付き本文の安全な作業は継続可能。
7. 本番既存V・Wを変更する前に完全バックアップ、EP-IDとGUIDの一致および更新直前値の検査を必須とする。既存Vの修復は原本に照らして欠損が証明できた行だけ。修正数を「原文復元V」「W関連記事復元」「他列補完」に分ける。
