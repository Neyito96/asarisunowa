## 最優先
1. Phase14に残る、実際に成功したGoogle Apps Script UrlFetchAppのRSS/JSON取得処理を再利用。外部API不可なら既存実証済RSS経路。最初に1件以上のGUID一致した公式説明、画像、音声、時間の実取得とログを証明する。取得成功を捏造しない。
2. 統合GASは1つのwriter所有者・一貫したスプレッドシートIDに限定。GAS lock、外部並列writerを制御する運用ゲートを設計。EP-ID/GUID、読み取り時の現セルと更新直前セルの同一性を再検査。予期せぬ競合があれば対象行の書込を禁止し、警告。列毎の逐次単独writerを乱立させない。
3. 行単位で V（未記入の場合公式生原文を全HTML/URL/改行付き取得）、W（本文・収録日・【関連記事】見出し/検証済みタイトル-URL対を保持し、出演者・イベント告知・共通案内を除去）、AC（リンク索引）、N/O/P、X/AT-AY等を**各列の現値・根拠に応じて埋める**。既存Vを勝手に書き換えない。ACにあるだけでは元VにURLが存在した証明にならない。
4. W清掃器は「出演・スタッフ」等のUnicode見出し揺れ、出演セクション後に関連記事、関連記事内のニュースレター混在、タイトルとURL紐付け不明、html anchor href、複数改行を扱う**状態機械パーサー**として改修。EP-00001〜00030の検証データと、EP-00004/6-11/23等の例外をテスト。
5. 決めたW品質条件を満たす場合だけ本番に書く。不明な記事リンクや出典欠落は保留。未検証行に旧清掃器を適用しない。既存W修正時は元値バックアップと差分をGitHubまたは実行履歴に保存。
6. 永続カーソル (PropertiesService)、100行単位の内部チャンク、実行時間上限による再開、処理済みEPの重複スキップ、エラー行隔離、更新対象列別実補填カウント、処理ログを実装。正常なら100→500行の連続巡回へ。
7. まずコードをGitHubのLAB branchで保存し、**実機の公式RSS/JSON取得→COPY write→再実行0差分→本番少数行write→再読込**まで証明する。自動時間トリガーは上記品質合格・並列writer競合対策確認後に設置。713行目以降の大量本番W生成はそれまで引き続き停止。
8. 進捗報告は「作成GASファイル名、実際にオンラインGASへ投入/実行したか、公式GUID取得件数、本番列別更新セル数、既存値修正セル数、保留数、カーソル、トリガー状態」を区別し、設計・GitHub保存を稼働と混同しない。
