## 目的
本番への書込がNO-GOである今、抽象RUNBOOKを追加するのでなく、COPY側で新着5件を収蔵したV19→V18の**実コードと依存実装**から、本番用の最小安全修正をGitHub LAB上で実装し、架空データでテストして証拠を提出する。

## P0 実作業
1. 既存GitHub上にV19/V18/LibraryOfficialEngineの完全コードがあるか確認。見つからなければ不足ファイル・具体的関数を1回で報告し、ユーザーに重複検索を依頼しない。オンラインコードが未取得なら、未取得と明記し、取得済み実コード範囲のみを元にテスト可能な分離モジュールを作る。実機コード同等性を推定しない。
2. LAB専用新規ファイルに、feed収集/既存GUID照合/採番割当/履歴状態遷移/台帳・V3証明/チェックポイントを分離して記述。RSS取得前に全体時間予算を開始。同期処理の制限・中断不可I/Oやタイムアウト発生の可能性も考慮し、deadline guardは保証でなくベストエフォートと明記。
3. 予約→台帳→V3→登録完了の各段階で強制停止する架空データテスト。EP-ID衝突（既存EP-06632保護）、他writer競合、RSS障害、1番組4件・全体11件、7日超停止、再実行時冪等性を試験。フィード完全性未証明ならSOURCE_PENDING。
4. 別GAS ScriptLockが共通ロックにならないため、単一writerを前提条件にする。採番 authority 未立証なら模擬でも本番へ書くコードを起動不能とするガードを置く。
5. READMEに現行V18との差分、依存元の検証状況、テストコマンド、テスト結果と残余リスクをまとめる。GAS環境へのデプロイ手順は草案のみ。既存の本番やCOPYのGAS関数を上書きしない。
6. 公式7番組＋旧SDGsのRSS取得失敗はSOURCE_PENDING。本番EP-06632とCOPY異GUID衝突は保護。新EP-IDを現時点で採番・台帳へ書込しない。
