# Phase 15｜概要原文取得→清掃 二段階処理の正式追加指令
2026-10-28。司令塔発行。ユーザーから清掃規則の明確な追加指示。

## 目的と処理順
1. 本番台帳 V列「概要原文」が空欄なら、対象エピソードの公式RSSまたは公式JSONからGUID完全一致の原文を取得する。取得元URL・取得日時を記録し、Vが空欄の場合だけ転記。既存Vは上書きしない。取得できない場合は保留し、Wを創作しない。
2. Vに原文がある場合（元々ある／今回取得した）、清掃規則でW列「概要清掃済み」を作る。Wが空欄の場合のみ書き込む。過去のHTMLタグ除去のみのCOPY試験成果は清掃合格と見なさず、本番へ移さない。
3. Wには**エピソードの内容説明本文と、必要な収録日**だけを残す。HTMLタグ除去だけでは不合格。HTML文字参照を復号し、段落を読みやすくする。
4. 【関連記事】以下、イベント・講演・展示・配信企画等の告知／申込案内、募集フォーム、ニュースレター、宣伝、購読案内、公式SNS・Discord・メルマガ、出演者名簿やリンク、定型案内／プライバシー文など、**エピソード説明本文以外の部分をWから除外**する。セクション境界は見出しで判別し、本文途中の必要事項を消さない。イベントそのものを取材・解説する回の主題説明は削らない（告知・申込情報だけ除く）。
5. 関連記事のタイトルとURLは消失させず、台帳「関連記事URL」など対応列に分離保管する（既存値は上書きしない）。出演者等も対応する構造化列への抽出を検討する。抽出可能性が低い場合は原文Vを保存してWだけ清掃。
6. COPYで実データ20件を「V原文、取得可否、W清掃後、除外したセクション、保留理由」として比較。品質を検証し、通過後は100→500→1000行バッチへ拡大。すでにCOPYにある不合格Wは別退避してから再生成。既存本番Wは勝手に上書きしない。
7. 公式データの取得ができない場合はその件だけスキップし、残りの正常行を連続処理。カーソル保存し次へ進む。実際のV取得セル数・W清掃セル数・保留数を別集計。
## 例
EP-00001：政治取材の長い編集委員2人が…リスナーさんからの質問は「なぜ高市政権で裏金関与議員が復活？」です。※2026年10月9日に収録しました。
その後の【関連記事】、記事リンク、出演者一覧、【おねがい】、【朝ポキ情報】、イベントや登録案内はWから外す。
## 実施の優先順位
ロボは既存Phase14/15コードを再利用し、実際にVを取得しWを生成する処理を完成させる。提案書だけで止めずCOPY更新実績と結果を提示。COPY、本番の更新数は区別する。本番書込とトリガーは承認済み範囲のみ。
