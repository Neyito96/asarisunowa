# Phase15｜改行保存とセル表示高さの正式追加規則（2026-10-28）

## データと見た目を分離
- V列の原文はHTML・改行・段落構造を失わず保存。既存Vを上書きしない。
- W列の意味的清掃では、必要な段落区切りを **実際の改行文字 LF (\n)** として保持する。空行は必要な場合だけ2連続LF (\n\n) とする。単なるスペース連結や全改行削除を禁止。HTMLの p/br を適切に改行へ変換し、不要な関連記事、イベント告知、宣伝などを除いた後、読める段落にする。
- 「改行を記号として残す」は、蔵側で利用可能な構造化文字情報を保全する意味と解釈する。セル値には文字列としてのバックスラッシュ+nではなくLFを保存。JSONへ出力する際には \n とエスケープして表現され、表示時に段落として復元できる。必要なら蔵側でCSS white-space:pre-line / pre-wrapを用いる。
- セルの行高と折り返しは **表示設定のみ**。長文で1行が数百pxになり台帳が読みにくくならないよう、W列は折り返し設定をしても行高は一定の適度な高さ（例：40〜60px程度）を維持し、全文は数式バー/セル編集時に確認できるようにする。既存シートの行高は現物確認のうえ変更し、勝手にシート全体へ適用しない。
- 清掃工程でV→Wへ変換する際、本文中の自然な改行と段落を保ち、不要セクション削除後の空行連続は整える。既存W値は上書きしない。COPYでLF保存・JSONの往復・蔵の表示を検証してから本番へ。
- 品質検査：段落数、LFの存在、消えては困る本文/収録日、混入しては困る関連記事・イベント告知・宣伝の検出。対象20件の比較に追加。
