# Phase15｜司令塔からの厳重改善指令：成果優先・再発防止・停止最小化
日付：2026-10-28

補填・収蔵ロボへ。ユーザーは作業速度の低下、同一種の誤りの反復、監査と報告のループ、未完成状態の長期化を深刻に懸念している。司令塔としてこれを正式な工程管理上の問題と認定する。

## 直ちに変えること
1. GitHubの計画書を増やすことを成果とみなさない。本番で実際に正しく埋まったセル数と品質、未処理件数の減少を最優先KPIにする。
2. 失敗発見時は原因・再現入力・修正コード・回帰テストを一組で保存。例：除外行でカーソルが進まない、出演者見出しの表記揺れ、関連記事の後置、ニュースレター混入、V/WのURL相違、他writer競合。不具合を次回バッチで再発させたら同じ処理を続けず修正。
3. 1件の保留を全体停止理由にしない。除外・未取得・原文不一致・清掃不合格はEP-IDごとに記録して次へ進む。誤書込・識別子不一致・並行writerによる破壊の危険があるときだけ本番全停止。
4. 直近の優先実務は本番242行目からの100行巡回とカーソル確定。既に本番39セル、監査39VERIFIEDを達成している。この実績を守った上で補填を前進させる。
5. 公式RSSで取得できる行はJSONの未完成に巻き込まない。過去JSONは別診断でHTTP→GUID→タイトル→配信日時のどこで落ちるか原因別に解決する。
6. 保留キュー187ログを重複排除してユニークEP件数・原因分類を提示し、除外対象を「エラー」と数えない。キューを再試行可能にする。
7. 100行処理の実測時間、実書込セル数、保留率を測り、十分に安定したら500行へ進める。すべて0セルでも「100行巡回」は巡回実績にとどめ、本番補填成果とは区別する。
8. 本番台帳に対するwrite ownerを明確化。他プロジェクトのトリガーが未確認なら無人トリガーは設置しない。既存値の無条件上書き、出典不明リンクの補完は禁止。
9. ユーザーへ毎回判断を求めない。既承認の正常範囲内は自律的に実行し、実行できない操作がある場合はプロジェクトURL・関数名・操作1点を提示。別チャットのため自分では実行できないときはそう明記する。

## 次の報告の必須形式（簡潔に）
本番の追加補填セル数（列別）／実際の処理範囲／次回カーソル／回帰テスト結果／ユニーク保留数と原因／JSON実取得成功数／競合writer状態／GitHubコミット。
「実装しました・検証しました」だけで終わらせない。まず確実な1バッチの本番処理を行い、その後の連続実行へ進む。

司令塔はコード・モックの反復を進捗の代替として受け入れない。速度と正確性の両立を求める。
