## 未接続部分の実装

新しい収蔵エンジンは作らず、既存V3が登録した台帳を公開へ接続する。

- `fetch-library-source.py`: 承認後のGoogle読取専用ADC/WIFを使用。実メタデータで範囲を限定し、台帳・除外履歴・V3項目状態をGETだけで2回取得。一致しなければ公開保留。私有ソースはリポジトリ外へ保存。
- `prepare-library-publication.mjs`: Phase 9/11の承認済みメタデータを再利用。対応する現台帳の公式URL・GUID・原文hash・清掃欄が変われば停止。既存の正しい記事見出しやSDGs情報を失わない。新規公開候補は既存V3のidentity VERIFIED / RSS_registered、GUID一意、行hash、登録時刻が一致した場合のみ受け入れる。新IDは採番しない。既存の概要編集器で内容/関連記事を分離し、疑義は停止。
- 既存 `export-library-public.mjs`: 段階生成と前回正常ディレクトリの復元を継続利用。原文や非公開のV3項目状態は公開しない。
- `library-publication.yml`: 既存プレイリスト同期Actionsの完了を起点に利用し、新たな定期タイマーを作らない。初期状態は停止。Google取得→準備→既存export→試験/Pages build→差分PR。既存の公開待ちPRがあれば停止、内容version不変ならPR/配信を作らない。自動公開の別承認フラグがない限りマージしない。
- 承認済み自動公開モードのみ、PR head照合付きmerge→既存Pages dispatch→Actions成功待ち→実HTTP manifest/version/番組件数読戻し。`verify-library-publication.mjs` はPages成功だけで公開成功を記録しない。
- 番組別の読取・登録・公開・失敗/再試行時刻の契約をoperationsに分離。V3登録証拠があるものだけ登録日時を使い、読み取り日時で代用しない。取得できない実行/番組別時刻はnull。将来の公開成功は読戻し証拠ファイルで記録する。

PR #243は既存PR #230への小さな積み重ね。V3の競合判定とMorning設定/導入/実行でALIB_AUTO_tickを検出して止める。既存のALIBトリガーを消すコードではない。稼働状況不明のまま同時収蔵を始めない。既存PR #234はPR #230より古い分岐、#225/#226は収蔵基盤、#232は出演者共通処理、#236はPhase 9の公式照合系であり一括mergeしない。

## 次段階の承認条件・復旧

本番有効化の承認はまだ求める段階ではない。まず実稼働GASのソース・配備版・トリガー一覧/実行履歴と既存診断を読取確認し、ALIB競合・V3 baseline/allowNew/切替時刻・人間除外を確定する。別チャットの母集団仕様確定も待つ。その後に対象プロジェクト/既存トリガー/適用差分/権限/試験対象/戻し方を具体化して承認を求める。

承認後設定が必要なもの: WIF providerと読取専用サービスアカウント（対象台帳閲覧のみ）、`library-publication-approved`環境の承認保護、`LIBRARY_PUBLICATION_ENABLED`。自動マージ/配信はさらに`LIBRARY_AUTO_PUBLISH_APPROVED`を別承認で有効化する。現時点では全て未設定/未有効化として扱い、実設定値は確認できていない。設定作成や認証変更は実行していない。

失敗時は新しいPR/配信へ進まず、既存公開スナップショットを保持。前回の公開へ戻す場合は対象データ変更をrevertし既存Pagesを再配信する（実行は承認後）。V3は既存stop関数で無効化する変更計画を別途提示し、ALIBなど他所有者のトリガーを削除しない。公開ブリッジは有効化変数をfalseへ戻して停止できるが、既に動く実行は明示確認が必要。台帳への復旧書き込みは本PRの処理に含めない。
