# RSS差分プレビュー：実データ接続の前提と検証メモ（2026-10-13）

## 確認できたこと
- エピソード図書館スプレッドシートの `エピソード台帳` は、A:台帳ID、G:外部ID、I:元ページURL、AG:取得元URL、AS:番組RSS URL を持つ（ヘッダー名と位置を実シートで確認）。
- 台帳の既存データに `取得元=Omny RSS` と `番組RSS URL=https://www.omnycontent.com/.../podcast.rss` が実在する。したがって **RSSの初回取得自体は既に実施された形跡がある**。ただし、定期トリガーでの自動差分取得は未確認。
- 朝日新聞ポッドキャストの公式OmnyページはドーナツなどのプレイリストとRSS feed導線を掲載する。
- PR #225 の `previewOfficialRssDelta_` はRSS2.0をHTTP取得し、`guid || link` と既知IDを比較する**読み取り専用の試作**。図書館のG列がOmnyのUUIDで、RSSのguidが異なる表現なら単純照合は不十分。

## 実行前に必要な修正
1. RSS `guid`、`link`、enclosure URLのclip UUIDを抽出し、台帳G列の外部ID／I列の元ページURLと正規化して照合。
2. 台帳AS列のRSS URLを取得対象リストとして利用。複数番組で同一エピソードが配信された場合も図書館では一意にする。
3. `人間除外` と `削除・除外履歴` を確認し、復活登録を防止する。
4. 公式RSSの疎通と最新エピソードの実測は未完了。現環境からRSS URLへの外部HTTPアクセスがDNSで失敗したため、取得件数・新着件数は断言しない。
5. 現在のGAS本番トリガー一覧は未確認。既存のSpotifyトリガーを変更せず、読み取り専用の比較結果から実装可否を判断。
