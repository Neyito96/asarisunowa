# 概要欄清掃ロボ（Issue #308）— 管理人向け操作説明

公式RSSの**原文だけを基準に**、V2台帳の「概要（清掃済）」「出演者」「関連記事URL」を点検・清掃する独立 Apps Script。原文は読むだけで変更しない。処理はすべて GAS の中で行い、結果は COPY の「清掃・結果」「清掃・進捗」「清掃・反映履歴」シートに残る。トリガーは作らない。

## ボタン（関数を選んで「実行」）
| 関数 | 何をするか | 書込 |
|---|---|---|
| `S1_点検` | 対象・列・RSS 7本・原文と台帳の突き合わせ件数を確認 | なし |
| `S2_清掃監査` | 全件を清掃・監査して「清掃・結果」に保存。時間切れなら「途中」と出るので、もう一度押すと続きから。全件後は変更分だけ再処理（何度押しても同じ結果） | COPYの結果シートのみ |
| `S0_進捗` | 「清掃・進捗」の内容を表示（判定別件数・処理位置） | なし |
| `S3A_COPYへ反映_試験10件` | 自動検査合格の行から10件だけ COPY 台帳へ反映 | COPY台帳3列 |
| `S3B_COPYへ反映_全件` | 自動検査合格の残りを COPY 台帳へ反映 | COPY台帳3列 |
| `S4_V2作業用へ反映` | 「清掃・結果」で **人の確認 列に OK** と書いた行だけを V2作業用台帳へ反映 | V2作業用3列 |
| `S5A_V2詳細保全_試験10件` | V2作業用ファイルの別タブに10件だけ保全: 「V2・収蔵詳細」に公式RSS原文（EP-ID＋GUID、17列）、「V2・清掃詳細」に出演者JSON・関連記事JSON・SNS保全URL・原文SHA256・版・判定・理由・原文状態。台帳34列は触らない | V2作業用の別タブ |
| `S5B_V2詳細保全_全件` | 上を V2作業用台帳の全EPに。書き換えない回（要確認・不合格・HOLD）も保存。原文は上書きせず、RSS側が変わったら「V2・原文変化履歴」へ。RSSに無い回は「原文なし（欠損）」。再実行は差分0（OK_NO_CHANGE） | V2作業用の別タブ |
| `S9_直前の反映を取消` | 直前の反映を元に戻す（その後に人が直したセルは戻さない） | 反映先 |
| `S8_診断` | 判定理由ごとに原因の行を数件だけ表示（調査用） | なし |

## 判定の意味（「清掃・結果」の 判定 列）
- **自動検査合格・目視未確認**: 原文との照合で問題なし。品質確認済ではない
- **要確認**: 見出しのない記事URL・非記事リンク・手で直した可能性のある旧値（`MANUAL_EDIT_PROTECTED`）など。自動では書かない
- **不合格**: 本文の消失などの重大所見。書かない
- **HOLD**: 公式RSSに原文が無い回（推測で補完しない）
- 品質確認済にするのは人だけ: 「人の確認」列に `OK`（必要なら「確認メモ」）

## 守っていること
- 書く条件: 書換可（自動値か空欄の列だけ）＋ 台帳の現在値が監査時の旧値と同じ ＋ EP-ID と GUID が一致。新しい値が空の列は書かない（既存を消さない）
- 手動訂正の保護: 旧値に原文に無い文字やURLがあれば人の手が入ったとみなし、書かずに 要確認
- 関連記事は「見出し＋URL」の組で「関連記事JSON」に保存（追跡パラメータを外したURLと元URLの両方）。台帳の「関連記事URL」列は従来どおりURLを空白区切り
- 出演者は原文の行をそのまま（リンク付き）で保存し、役割・氏名・所属・リンクに分けたものを「出演者JSON」に保存。氏名は推定しない
- 反映前後の値は「清掃・反映履歴」に全件残る（取消に使う）

## V2作業用へ自動検査合格分も反映したいとき
COPY で S3A/S3B の結果を見て問題が無ければ、コード先頭の `v2ApplyLevel: 'HUMAN_OK'` を `'AUTO_PASS'` に変えて保存し、`S4_V2作業用へ反映` を押す。

## コードの更新
`gas/summary-cleaner/dist/SummaryCleaner.js` は自動生成（`node scripts/ledger-v2/build-cleaner-gas.mjs`）。清掃規則の元は `scripts/ledger-v2/summary-cleaner-v4.mjs`（Node の試験と同一コード）。

## 途中で止まったとき
- `S2_清掃監査`: 「途中」と出たらもう一度押す（続きから）。
- `S3`/`S4`: 書く前に「清掃・反映履歴」へ旧値を残す（状態「書込中」）。時間切れ等で止まっても、もう一度押せば、書けていた列は履歴を「OK(回収)」として整え、残りだけ書く。`S9` で取り消せる。

## 初回実機（2026-11-11, COPY）
S1 点検 OK（台帳6,580件・原文あり5,464件）→ S2 全件 約50秒 → S3A 10件 → S3B 1,933件（合計1,943件をCOPY台帳へ反映、再実行で差分0）。判定: 自動検査合格1,944・要確認2,271・不合格1,249・HOLD（原文なし）1,116。V2作業用へは未反映（人の確認OKの行が0のため）。

## 2026-11-12 抜き取り確認と残件の整理
- 抜き取り: 原文がCOPYにある26件をNodeで同一コードにより再現し、原文と比較。自動検査合格18件で 本文の欠落0・記事URLの欠落0（見出し付きで保存）・出演者の行とリンクの欠落0。要確認7件・不合格1件は書かない判定のまま。
- V2側の保存先: V2作業用ファイルに別タブ「V2・清掃詳細」（関連記事JSON・出演者JSON・SNS等保全URL・原文SHA256・清掃版・判定）を S4 実行時に自動作成・更新（34列の台帳は増やさない）。
- `v2ApplyLevel` を `'AUTO_PASS'` に変更（コミット 3f08715）。**GASへの配置と S4 実行は未実施**（実行に使う Mac の Chrome が未接続のため）。
